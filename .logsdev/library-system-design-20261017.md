## 1. 现状对齐（2026-10-17 实测，不是回忆）

| 项 | 现状 | 证据 |
|---|---|---|
| 库层级 | 只有 **库根 → 库 → 资料**，没有「库组」层 | `<库根>/*/kb.json`，12 个库平铺在库根 |
| `kb.json` 字段 | `id/name/description/tags/schema_version/knowledge_type/embedding/chunking/vector_store/(site/scan/structure)` | `kbctl/core.py:34 DEFAULT_KB_JSON`；**没有任何分组字段** |
| 库分类 | `knowledge_type` 是自由字符串，实际只用两类：`source code and documentation`(1) / `科学研究与应用类技术验收报告，自然科学基金`(11) | 12 个 kb.json |
| 库列表页 | `/knowledge` 是**写死的卡片网格**（`grid` + 每库一张 `<Link>`：名称 + slug），无分组、无视图切换、无动效 | `KnowledgeView.tsx:326` 分支 |
| 库内视图 | 列表/表格；`?view=shelf` 已剥除并静默落到 list | U3 落实（2026-09-29 INTERACTION） |
| 书架/卡片代码 | **在死链上**：`ShelfView`/`CardView` 只被 `KbWorkspace.tsx` 引用，而 `KbWorkspace` 无人引用（0 引用）。同链还有 `KbGroup` v2（树 + 色相）、`KbMirror`（镜像）、`kbViewStore`、`kbGroupDnd`、`kbLayout`、`MirrorPicker`、`ConfirmCard` | grep 实测 |
| 组织视图落盘 | 只存 localStorage，界面标「本地仅」（U5 要求的后端落盘未做） | `kbViewStore.ts`；INTERACTION 记录 |
| 资料形式 | `v2-scan` 遍历 `source/` 下**所有**文件，只对 `.pdf` 特殊处理；**其余一律 `decode("utf-8","replace")` 当正文** | `pipeline2.py:225 / 348` |
| 多媒体 | 无任何音视频/图像通道 | 全仓库无 `mp3`/`mp4`/`audio`/`whisper` 处理 |

**由此得到两个必须先说的结论：**

1. 用户要的「资料库组 + 书架/卡片形态」= 复活 `KbWorkspace` 那条死链，代价不是从零写，但也**不是打开开关**：视图要接到 `/knowledge`，分组要按 U5 落盘。
2. **多媒体现在是坏的**：把 `.mp4`/`.png`/`.xlsx` 放进 `source/` 会被解成乱码正文，进 chunks、进 BM25。所以多媒体不是「加个视图」，而是「先分流」。

## 2. 概念澄清：横向 / 纵向

这两个词来自**科研经费管理口径**，判断依据只有一条：**钱从哪来、谁立项**，与资料主题无关。

| | 纵向课题 | 横向课题 |
|---|---|---|
| 立项主体 | 上级科技主管部门（国家/省/部委/基金委） | 企业、事业单位等委托方 |
| 经费来源 | 财政拨款，走预算与审计 | 委托方合同款，走合同节点 |
| 典型形态 | 国家自然科学基金（面上/重点/青年）、国家重点研发计划、省基金、博后基金、人才项目 | 技术开发 / 技术转让 / 技术咨询 / 技术服务（「四技合同」）、产学研合作、企业委托开发 |
| 交付与验收 | 任务书 → 年度进展 → **结题验收报告**，进入国家验收体系 | 按合同交付物与节点验收，通常无国家层面结题 |
| 管理特征 | 批准号（如 `62076099`）、负责人、起止年限 | 合同号、甲乙方、经费与节点条款 |

对上用户的资料：**自然科学基金项目验收报告 = 纵向**；**产学研项目合同、企业合作合同 = 横向**。

但「是不是就包含横向、纵向两个方面」——**不是**。两个漏洞：

- 项目类里还常有**第三类**：自筹/校内基金、国际合作、以及走政府采购的委托（横纵都不完全归类）。实操上按「自筹/其他」单列更稳。
- 用户的另外三类（科研论文与研讨博客、个人积累、外部技术文档）**根本不在项目维度上**——论文是"成果"，个人笔记是"个人资产"，langchain_docs 是"第三方公开资料"。它们没有"谁给我钱"，硬塞进横纵会把分类体系压垮。

所以正确做法是：**分类不是一棵树，而是几个互不替代的维度（分面）**。横/纵只是其中一维。

## 3. 分类模型：三个分面 + 受控词表

| 分面 | 取值（受控） | 落盘字段 | 说明 |
|---|---|---|---|
| **来源/归属** provenance | `纵向项目` / `横向项目` / `自筹其他` / `个人` / `外部公开` | `kb.json.provenance` 或资料级同名字段 | 回答"这份资料是谁的、谁给的" |
| **体裁** genre | `项目文档` / `合作合同` / `学术文献` / `个人积累` / `外部技术文档` | `kb.json.knowledge_type`（收敛为受控词表） | 决定**处理方式**（分块、抽取方案） |
| **载体** media | `text` / `pdf` / `pdf_scan` / `office` / `image` / `audio` / `video` / `dataset` | 资料级 `sources.media`（新增） | 决定**解析通道**，不是类别 |

- 用户说「多媒体不是单独一个类别，而应分布在更上层的资料库里」——**这个判断是对的**：media 是载体分面，一条录音可以属于"横向项目"、一张实验照片可以属于"学术文献"。
- **资料级**字段（`sources` 表）现有 `path/title/tags/kind/online/last_seen_sha256`；建议加 `genre` 与 `media`，取值优先从**目录约定**推断、其次文件扩展名，最后允许人工覆盖。
- **库级**保留 `knowledge_type`（体裁）+ 新增 `provenance`；`tags` 继续自由。分面组合示例：
  - `横向项目 × 合作合同 × pdf` → 企业合作的合同扫描件
  - `个人 × 个人积累 × text` → 源码研习笔记
  - `外部公开 × 外部技术文档 × text` → langchain_docs

> 工程量提示：把 `knowledge_type` 收敛成受控词表要改 12 个 kb.json 的取值（现取值是整句话），属于一次性迁移脚本 + 校验。

## 4. 层级模型：库组落在哪

用户要的四层：

```text
资料库系统 → 资料库组（书架/卡片堆）→ 资料库（一本书/一张卡）→ 资料（多种形式）
```

建议**不引入中间目录**，库组作为**视图层数据**独立落盘：

```text
<库根>/
├── _layout.json          ← 新增：库组的唯一真源（跨库关系）
├── README.md
└── <库目录>/              ← 不变：仍平铺，仍是自包含单元
    └── kb.json
```

`_layout.json` 草案：

```json
{
  "schema_version": 1,
  "revision": 3,
  "groups": [
    {"id": "grp_2f7c1a9b", "name": "纵向项目", "parent_id": null, "child_ids": ["grp_9d3e0b42"], "kb_ids": [], "hue": "sky"},
    {"id": "grp_9d3e0b42", "name": "自然科学基金", "parent_id": "grp_2f7c1a9b", "child_ids": [],
     "kb_ids": ["kb_7ae8af441bb44a87b7f9958a46246103"], "hue": "sky"}
  ],
  "ungrouped_order": ["langchain_docs"],
  "mirrors": []
}
```

> 这是**示意的形状**，字段定义、约束与校验以子方案 §3–§4 为准（引用用 `kb.json.id` 而非目录名；`collapsed` 属设备偏好，不落盘）。

> 落盘格式（schema / 不变式 / 写协议 / 软删除 / 接口 / 验收）的细化见 [layout-persistence-design.md](layout-persistence-design-20261017.md)。

理由与替代：

- **不建 `<库根>/<组名>/<库>/` 中间目录**：后端发现库的唯一依据是库根下的 `kb.json`，加一层要改 discovery、改 12 个库的物理位置，并破坏"一个库 = 自包含单元，可整体拷贝/迁移"。目录即权威这条原则不该为视图让路。
- **不放各库 `kb.json`**：分组是**跨库**关系，写进单库会出现"这个库说自己属于 A 组、A 组却不认"的自相矛盾。
- **沿用 code 里已有的模型**（`types.ts`）：树深上限 3（领域 → 子组 → 库）、`hue` 领域色相、`mirrors` 只存引用边不复制实体、结构操作"只动视图、永不触碰 `KnowledgeBase` 实体"、每次结构操作压整体快照供撤销。这套约定已被 U5 认可，直接升级为后端落盘即可。
- **备份优先级**：`_layout.json` 是用户资产（手工排布成果），进 P0（与 `.datascripts/`、`datadb/` 同级）。

## 5. 视图形态与动态效果

三种视图**读同一份 `_layout.json`**，只是渲染不同：

| 视图 | 映射 | 适合 | 现状 |
|---|---|---|---|
| 列表/表格 | 组 → 分区标题；库 → 行；资料 → 行 | 筛选、批改、比较 | 已用于库内；列表页当前是写死卡片网格 |
| **书架** | 组 → 层/书架；库 → 书脊；点开 → 库内 | 多库浏览、排布 | `ShelfView.tsx` 存在但在死链上 |
| **卡片堆** | 组 → 堆；库 → 卡片；点开 → 细节面板 | 视觉浏览、拖拽归组 | `CardView.tsx` 同上 |

动态效果清单（按性价比排序，**都要能被关掉**）：

1. **拖拽归组 / 层内重排**：`kbGroupDnd` 已实现（含占位、就地确认卡 `ConfirmCard`）。必须同时给键盘路径（`⌥+↑/↓` 移动、`M` 移动菜单），否则不可访问。
2. **抽出/归位**：拖动时卡片抬起、影子留位——已实现，检查 `will-change` 与 `transform` 性能。
3. **翻页/展开**：书架层折叠、卡片堆展开（`transform + opacity`，`≤220ms`），用 `@media (prefers-reduced-motion: reduce)` 直接关掉。
4. **镜像指针**：镜像的库在原组显示为虚线描边 + 指针，避免"是不是复制了一份"的误解。
5. **撤销**：结构操作后 3 秒内可撤销（快照栈已具备），给动效但别阻塞。

**视图状态进 URL**（项目既有原则：用户选了什么状态要能刷新还原）：`?view=list|shelf|deck`、`?group=<id>`；
**分组成员关系进 `_layout.json`**（那是数据，不是 UI 状态）。搜索/筛选时切回平面列表，避免"书架里搜不到"。

规模约束：库 > 50 或组 > 8 时书架层需要虚拟化或分页；当前 12 库不需要，但设计上要留出口。

## 6. 增删改查矩阵

| 对象 | 增 | 删 | 改 | 查 | 落盘 / 接口 |
|---|---|---|---|---|---|
| 资料 | 放进 `source/`（库页上传） | **软删除**（下线 `online=0`，保留历史引用）；物理删除另立流程 | 重命名、移动、重新绑定 | 列表/搜索/阅读 | 已有：`v2-scan`/`organize`/`v2-rename`/`refresh`；上传接口待补 |
| 资料库 | `init`（新库）/ `adopt`（已有目录） | 删目录（须先确认，不可逆） | 改显示名、`description`、`tags`、分面字段 | `/api/libraries`、`tree` | 已有；改分面字段走 kb.json 编辑 |
| **资料库组** | **新增**（`POST /layout/groups`） | **新增**（删组只散成员，不删库） | 改名/排序/色相/折叠/**镜像** | 读 `_layout.json` | **新增**：`GET/PUT /api/layout`，或按组粒度的 CRUD |

原则沿用：**组操作永不触碰库实体**；删组时成员退回未分组，不允许"删组连带删库"。

## 7. 资料接入通道（按载体分流）

这是多媒体能不能进库的前提。建议按 `media` 分流，**二进制一律不进正文**：

| 载体 | 通道 | 产物 | 检索 |
|---|---|---|---|
| `text` (md/txt) | 直读 | 正文 | BM25 |
| `pdf`（有文本层） | MinerU 或已有解析 | `parsed/<rel>/markdown.md` | BM25（现路径） |
| `pdf_scan`（无文本层） | OCR | 同上 | 同上 |
| `office` (docx/xlsx/pptx) | 离线提取 | `parsed/<rel>/markdown.md` | 同上 |
| `image` | 视觉描述 + OCR | `parsed/<rel>/caption.md` | 文本化后检索 |
| `audio`/`video` | ASR 转写 + 分段 | `parsed/<rel>/transcript.md`（带 `[00:12:30]` 时间戳） | 文本化后检索，locator 用时间戳 |
| `dataset`/`code` | 登记但不进正文（可按需做符号摘要） | 无 | 不检索，只做清单 |

要点：**统一落到 `parsed/<相对路径>/…`**，这样阅读、全文索引、证据定位、备份优先级全部复用现有机制，新增的只是"解析器"。多媒体的 locator 不是字符区间而是时间戳/帧号，`evidence` 的核对逻辑需要按 media 分派。

**当前必须修的一处**（独立于本方案）：`v2-scan` 把未知二进制当 UTF-8 解，请先加"非文本扩展名不进正文"的判断。

## 8. 问答与检索（按类型分层）

- **分块按体裁**，不要一套参数打天下：
  | 体裁 | 分块单位 | locator |
  |---|---|---|
  | 合作合同 | 条款（"第X条"） | 条款号 + 字符区间 |
  | 项目验收报告 | 章节树（现有 `sections`） | 章节 + 字符区间 |
  | 学术文献 | 段落级 512/64（现有默认） | 字符区间 |
  | 个人笔记 | 片段（可小于 512，允许空片） | 字符区间 |
  | 音视频 | 转写分段（~30s/段） | 时间戳 |
- **检索顺序**：元数据过滤（库组/库/体裁/年份）→ BM25（现有 FTS5）→ 可选 dense 重排（U2 已定：向量是可增强、不阻塞）。**filter 先行**能极大减少"跨体检索"噪声。
- **证据与幻觉**：答案必须带 `quote` + 定位；沿用现有"唯一逐字匹配才生成正文字符位置，匹配不到不虚构位置"。合同与验收报告里的**结论性表述**（"已完成""达到指标"）不得由模型改写为事实断言。
- **跨库问题**：多库命中时按库分组呈现，明确标注来源库；**不做跨库合并断言**（同一结论有两个来源才叫互证，同内容两次出现不算）。
- **评估**：建 40 条左右 QA 集，按体裁分层（事实 / 对比 / 枚举 / 无答案），指标 `hit@k`、证据命中率、无答案正确率、P95 延迟。没有评估集，"检索好不好"就只能靠感觉。

| 期 | 内容 | 前置 | 验收 |
