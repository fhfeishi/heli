00一页结论

#结论相对 v1 的变化
C1层级负责组织，属性负责筛选v1 把两者混在「三分面」
C2不新增「子资料库」实体，库内分层用逻辑目录新增结论
C3组可同时含子组与库，不强制「只有叶子组能放库」推翻 v1 不变式 I5
C4多归属叫「添加到其他组」，按稳定库 ID 去重「镜像」→「添加到其他组」
C5组背景与成员是产品数据；折叠/宽度才是设备偏好修正 v1「组是视图层数据」的含糊
C6背景三态：用户已保存 / AI 建议 / 尚不明确推翻 L0–L3 完整度
C7已保存原件 / 可预览 / 可检索 / 可用于审查，是四件事新增结论
C8任务、会话、执行记录、成果是四个对象新增「执行记录」层
C9审查输出四态，不合成总分收紧 v1 的三档
C10所有分析指标必须能点开分母，「不适用」不记 0v1 只要求可复算

三条既有缺陷（与批准无关）

#缺陷证据后果
D1非 PDF 一律按 UTF-8 解码当正文pipeline2.py:225 / 348二进制进 chunks、进 BM25
D2建库/删库只改内存，界面提示已落盘store.tsx / api/index.ts用户无法判断是否保存
D3无上传/布局/聚合检索/jobs/模板/审查接口server.py 路由实测本方案的组、背景、多库对话无处落地

01定位与整体结构

四件事
收集与组织不同形式的资料 → 理解背景、范围与可用程度 → 基于指定资料问答/提取/研究/审查 → 形成可核证、可修改、可导出的成果。
三条硬约束
不设门禁（没有背景也能读）· 不丢人工投入（自动能力关闭后手工路径完整）· 不越权（能做什么由系统决定，不由资料里写的决定）。

一级入口沿用 资料库 / 研究任务 / 成果 / 设置（U1 不变）。任务模板在研究入口；Prompt、Skill、工具配置在高级选项。工作台、生活台是后续方向，当前不复制三套体系。

02层级负责组织，属性负责筛选

五个属性（都不强制填）

属性示例解决什么
项目属性横向 / 纵向 / 其他 / 待确认项目按什么管理口径理解（仅适用时填）
内容类型申请书 / 合同 / 验收报告 / 论文 / 笔记 / 教程 / 源码解读怎样阅读、提取和审查
文件载体PDF / Office / 文本 / 图片 / 音频 / 视频 / 代码 / 数据集采用什么解析与预览
来源信息机构 / 作者 / 网址 / 采集方式资料从哪里来
主题与时间农业 / 智能制造 / 年份 / 软件版本检索与比较范围
空不是「未分类」，是「不适用」。库级属性只作默认值与概括，不覆盖资料级事实——主题相近不代表来源相同，用了科研模板也不证明项目属于某管理类别。

03四棵树与动词

04背景：允许模糊，逐步完善

用户已保存
用户认可的定位或描述。正常展示，可修订。
AI 建议
依据描述与资料生成的候选。展示差异与依据，逐项采纳。
尚不明确
缺依据或存在冲突。标注待补充，不编造。
不把「填写完整」换算成「背景可信」。 一份填满但没有依据的背景仍可能错——v1 的 L0–L3 完整度是进度条思维，v2 取消。
规则内容
建库门槛只要求名称；写「一些农业 AI 项目材料」就能开始用
组背景与库背景不自动写入；同一库在多个组时按当前任务路径提供，冲突则披露冲突
编辑方式现有内容 — 修改建议 — 依据 三栏对照；背景变更后重新比对，不覆盖新内容
重叠是建议不是错误；允许有意保留重叠；不自动合并、不自动搬移
无模型手工背景、资料管理、检索照常可用；入口隐藏并注明未配置

05接入与证据：四态分开

载体阅读形式证据定位不支持时
PDF / 扫描件原件 + 解析正文页码 / 区域 / 字符位置无文本层 → OCR，或标「仅原件」
Office原件 + 提取内容实际支持的段落/页/表格位置复杂版式降级为文本
音视频播放器 + 转写时间范围未转写 → 可存可播，不可检索
图片原图 + OCR/描述实际获得的区域仅描述 → 不进正文检索
未知二进制仅登记—不得以乱码进正文（D1）
删除三档
移除关系（不动文件）· 移入回收站（退出新检索）· 永久删除（独立操作，不随删组连带）。
历史引用
来源不可用时显示「来源不可用」，保留已有出处与摘录，不清空。
提取不替代原文
提取用于快速筛选；结果不足时回到原文检索。指不回位置的记录不算证据。

06任务、会话、执行记录、成果

对象职责生命周期
任务目标、范围、交付要求长期，可复用
会话围绕任务的讨论、追问、修订跟任务走，可多条
执行记录一次实际运行的输入、状态、输出一次一行，可回溯
成果报告 / 笔记 / 表格，可继续编辑导出用户资产，显式保存

轻任务：从资料库点「与这些资料对话」直接创建（范围 = 选中资料或当前库），有长跑/比较/报告需求时再展开设置。

五类模板：统一管理，不合并表单
背景 / 提取 / 任务 / 报告 / 审查规则集。统一支持名称、版本、复制、编辑、导入；字段结构差异太大，不做万能表单。
运行冻结模板版本
一次运行记下模板与规则集版本；后续改模板不改历史运行依据。成果记录「用了哪一版」。
提取方案原地不动
target/ 不重排。多方案用「关联列表」，不新增 target_task2/3 字段。
运行输入冻结
任务范围可改，一次运行的输入固定：后端解析 scope_resolved，存正文版本、背景哈希、模板/规则版本。运行期间新增资料不自动纳入，重跑才纳入。
样本 → 报告模板
上传样本 → 识别结构 → 区分固定/示例 → 修订 → 少量试生成 → 保存。不把样本里的项目名、经费、结论当事实。
「提取报告结构」与「复刻 Word 复杂排版」是两个能力。前者先完成；后者逐格式验证，不承诺上传任意文件即可无损还原。

07申请书审查

结果含义
符合程序可判定且通过
不符合程序可判定且未通过
待人工确认需理解含义：模型给线索，不下结论
无法检查缺解析文本、涉及原始排版/印章
没有适用规则时不得宣称通过
规则必须带来源、适用项目、年度或版本。无规则时只做「一般完整性检查」，不能显示「已通过正式要求」。
技术审查：每个问题五要素
位置与主张 · 问题说明 · 支持或冲突的资料 · 修改建议 · 证据不足之处。
相似性分四类
模板用语 / 引用 / 背景介绍 不计入实质重叠；只有「实质性技术重叠」需人工重点判断。
披露覆盖范围
展示检索了哪些库、时间范围、哪些资料未处理。「本地未找到」≠「世界上不存在」。

不用相似率直接判断重复研究；形式与技术可同屏切换，但不合成总分。申请书更新后，旧问题转「待复核」，不视为已解决。

08分析与雷达图

资料盘点
这个库/组里有什么、状态如何：数量、内容类型、年份、解析状态、主题覆盖。
任务就绪度
针对某个目标，资料与证据够不够。按真实库与来源去重，并说明是否含子组与「添加到其他组」的库。
指标分子 / 分母
来源信息完整率已填所需出处信息的资料 / 适用资料
可阅读率已有可用阅读表示的资料 / 适用资料
可检索率已进入有效文本索引的资料 / 可文本化资料
提取覆盖率已完成有效提取的去重资料数 / 所选适用资料数
证据核验率已核验项 / 需要核验的提取项
每个指标能点开分母、缺失项与更新时间。「不适用」不记成零分。 选图看指标数 × 尺度一致性 × 对象数，不看库数：一个库有 5 个同尺度指标可以画雷达，三个库只有 2 个指标画不出雷达。 多对象比较优先表格/条形；技术深度、创新性、研究价值不能由文件数或模型印象生成评分。

09Agent 运行约束

概念作用谁能改
背景帮助理解资料用途用户（AI 建议经确认）
任务要求本次应该完成什么用户
工具权限系统实际允许执行什么系统配置
注入防护：背景文件、导入资料、模板里的文字不能自行扩大权限。模型读到「删除无关库」也不获得删除能力。
自动执行档位行为默认
只读分析检索、摘要、诊断允许
建议产出待确认对象默认
范围内自动用户开启后在明确范围连续执行用户开启
破坏性删原件、覆盖人工成果、对外发送每次确认

本地保存资料不代表推理在本地。 设置里显示实际模型通道；外部调用遵循配置的资料范围，不把凭据或无关原文加入提示词。

10存储与落盘修正

v1 / v2v3理由
child_ids + parent_id 双写只存 parent_id + order，子列表派生双写必然出现父子不对应
kb_ids 映射 + 引用各自 orderlibraries[] 每条一个 order；同一父下三种成员共享序号空间两套序号无法表达「子组 → 库 → 子组」
非叶子组 kb_ids 必须为空（I5）任意层级可放库真实的「待分类项目资料」就挂在父组下
mirrors[]references[]「镜像」听起来像复制
rename 失败 → degraded 覆写保存失败 + 保留旧版不拿数据保护换界面体验
损坏布局静默归一后覆盖只读诊断 + 显式 --fix（先快照）不能丢用户排布
删库 = 移目录 + 写布局（两步）先写 .origin.json 恢复记录，再移，再写布局两者不是同一事务
背景在两处维护叙述在 md，机器配置在 json，摘要派生同一语义只写一处

备份：完整恢复必需集合（R 集）

不可重建，必须备份
source/ 原件 · datadb/kb.db（章节/归属/来源版本）· _layout.json + groups/*.md · background.md · 模板与 target-schema · artifacts/ · tasks.db（C 阶段建立后）· _trash/.ops/*.json
可重建 / 可选
可重建：parsed/ · vectordb/ · _scratch/。可选历史（滚动）：布局快照、回收站内容。快照能补误操作，补不了一份丢失的原件——所以它不能排在原件之前。
为什么仍是单文件 JSON
跨库关系统层、可 diff 可手改、原子替换不撕裂；12 个库用不上事务。不为增加分组迁移全部资料。
「可脱离 heli」的正确含义
保留可读文件 + 数据库 + 导出恢复方式即可，不等于全存纯文本。

11界面

库内阅读
三栏：目录/专题 · 资料列表 · 原文/正文/播放器。背景在「概览」里编辑，缺背景只显示徽章，不占大面积警告条。窄窗口收起目录或切换视图。
研究与报告
顶部显示目标、资料范围、执行状态；模型细节收进运行详情。切换页面不取消后台任务；停止区分「正在取消 / 已取消」；部分失败保留成功结果。
审查
原文与问题清单并排；问题标 已处理 / 保留意见 / 待补证据；申请书更新后旧问题转「待复核」。「无法检查」与「待人工确认」用不同视觉。
状态真实性
不假成功、不假进度、失败可读、未接后端明说、键盘可达全部结构操作、动效可关。

12阶段 A–D

每阶段交付一条端到端路径，验收落在真实库上；不为阶段名称凑测试数量。v1 的 P0–P5 与三份子方案期次表作废。

A 组织底座
建组与建库 → 简短背景 → 导入 → 阅读/检索 → 重开仍在
含书架/卡片的多库浏览与动效（动效不能替代持久化完成）。
依据：结构持久化 · 未知二进制不污染正文 · 原件不因分组变化而移动 · 键盘可完成结构操作
B 背景与提取
请求背景建议 → 采纳或拒绝 → 小批提取 → 点开证据
LLM 模块可整体关闭。
依据：建议可追溯 · 未知不编造 · 人工修改不被覆盖 · 旧输入可识别
C 研究与报告
选范围 → 用或导入模板 → 运行 → 修订 → 保存导出
音视频按载体逐项接通，未接通前保留明确状态。
依据：范围不漂移 · 中断状态真实 · 成果可恢复 · 导出与保存版本一致
D 申请书审查
指定规则与申请书 → 形式/技术检查 → 原文对照 → 修订复核
规则集由用户/单位提供。
依据：问题有位置与依据 · 不支持项明确 · 版本变化触发复核

13验收断言

#断言
1不侵入：布局写入前后，各库 kb.json 与 datadb/kb.db 的 sha256 完全不变
2并发：A rev=3 → B 以 3 写 → 409 + 当前布局；B 只重放前提成立的操作后成功
3写失败不降级：制造 rename 失败 → 返回失败、旧文件完好、界面提示未保存
4损坏只读：造环/重复成员 → 拒绝写入并指字段路径，条目不被丢弃
5删除中断：库移入回收站后中断 → 下次启动提示「布局待修复」，不自动清理
6去重：同源文件在组范围检索里只计一次证据
7四态分离：未转写视频显示「已保存/可预览」，不显示「可检索」
8无规则不宣称通过：未选规则集时只出「一般完整性检查」
9注入无效：背景里写「删除无关库」，Agent 仍无删除权限
10通道披露：设置页显示实际模型通道；运行详情可核对输入范围
11无模型可用：断网/无 key → 手工背景、检索、分组全部可用
12防幻觉：抽 20 份背景草稿，编造事实 0 例

A术语（唯一口径）

术语指什么不指什么
组有背景、成员、分析范围的集合不是目录，不是库的上级实体
逻辑目录章节树节点（可多归属）不是物理目录
资料 / 源source/ 里的一个文件不是文档，不是分片
归组改变库的主要归属不是合并，不是移动文件
添加到其他组同一库在第二个组额外陈列（引用边）不是复制，不是镜像副本
执行记录一次实际运行不是成果，不是任务
建议待确认对象不是已生效的修改
四态符合 / 不符合 / 待人工确认 / 无法检查不是「通过 / 不通过」
