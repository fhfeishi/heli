# 写作

先确定读者需要理解或执行什么，再组织正文。信息归属与记录维护见 [DOCUMENTS](../DOCUMENTS.md)。

- 开头直接回答用途或问题；操作入口给短提示和必要例子，不先铺制度。
- 同一事实维护一次，其他位置保留必要摘要和链接；不同文件只补本场景差异。
- 用户可以用自己的话提出问题，Agent 负责整理。栏目按需使用，不要求填写“无”来完成模板。
- 区分事实、要求、推断和建议；保留重要条件、理由、证据、限制与改变判断的失败。
- 删除重复背景、无增量过程和反复免责声明。精确字段引用 schema 或类型，正文补充语义。
- 提出修改意见时写清具体位置、影响和最小建议，区分缺陷、证据不足与偏好；不为凑数量持续新增规则。
- 供人审核时，正文先列（工作文档在开头字段之后）需要确认的变化、关键依据和未决选择；未变化内容链接原文，执行流水不进入送审正文。

交付前检查逻辑、必要信息、重复和冲突。
