# Brief — round 001

## 背景 goal

资料管理系统 heli 的**资料库管理界面**：

- **卡片视图**：分组的资料库卡片参考 Apple 折叠窗口；组未展开时卡片叠在一起，并显示组名。
- **书架视图**：一个资料库组 = 一个书架；组内每个资料库像书一样立在架上。鼠标划过书脊 → 过渡到书面（正面），书面展示该资料库的基本信息（字段待补全）。
- **共性**：同组资料库共享分组归属，并有相近的颜色等视觉特征；动画要克制、可跟手。单个资料库打开后，默认进入该库的管理界面（库内资料预览）。


## 现状摸底（Step A.1，已填）

- 资料库总览（组 + 库，三视图）：`heli-web/src/views/KnowledgeView.tsx`（1714 行）。
- 路由：`heli-web/src/app/router.tsx` — `/knowledge?view=card|shelf|list`；单库 `/knowledge/<slug>`；库内文档 `/knowledge/<slug>/doc/<sourceId>`。
- **卡片 / 书架 / 列表是同一个 `/knowledge` 页面内的 URL 视图切换**，不是三个入口，也不是库内视图。`useViewMode` 负责读写 `view`，缺省为书架。
- 库内管理页：`heli-web/src/views/LibraryView.tsx`。卡片、书脊和列表项已经通过 `Paths.kb(library.id)` 打开单库，无需另建落地页。
- `KnowledgeView` 已有 `ViewMode`、组折叠叠卡、组 `hue`、书架书脊上色与卡片色沿共用。
- 叠卡实现位于 `GroupStack`（当前 318–381 行）：最多渲染前 3 个库，按 `top / left / right / zIndex` 错位，只有顶卡在 hover 时上移；调用点在 `renderGroup`（当前 1513–1517 行）。
- 折叠状态是 `KnowledgeView` 内的 `collapsed: Set<string>`；搜索时强制展开。`GroupStack` 目前只接收 `libraries / hue / onOpen`，accessible name 不含组名。
- 组名已经显示在折叠组标题中；本轮保留这一处可见名称，不在卡面重复加一层组名标签。
- 现有 `Library` 已含名称、说明、资料数、可检索数、年份跨度、创建 / 更新时间与组关系；本轮增强不需要新 API 或新字段。

含义：本 goal 是**增强现有卡片与书架**，不是从零做新页面。

## 实施方案 · 卡片叠卡

### 视图、数据与导航约定

- 三视图继续共用 `KnowledgeView` 的 `libraries / groups / filtered / collapsed`，通过 `?view=card|shelf|list` 切换；不新增路由或页面。
- P1 / P2 共用现有 `Library`、`Group`、`spineSet` 与排序结果；叠卡顺序沿用 `members` 当前顺序，不另建叠卡数据层。
- 单库继续进入 `Paths.kb(library.id)` 对应的 `/knowledge/<slug>`（`LibraryView`）；点击叠卡只展开组，不直接打开第一个库。
- 书架书面的最小信息集定为：**资料库名称、资料总数、可检索数、最近更新时间、年份跨度（无则省略）**；组名 / 归属色沿用现有 `Group.name / hue`。不新增封面图、标签或伪造字段。
- 动效无需新增用户开关，但必须尊重系统 `prefers-reduced-motion`；不引入动画库。

### P0 — 数据形状与信息架构（已由现状确认）

- **做**：复用上述字段、组关系、排序和空态；空组继续显示现有拖放提示，有成员的折叠组才显示叠卡。
- **不做**：不改 `api.ts`、后端 schema，不为叠卡补聚合接口。
- **入口**：`KnowledgeView.tsx`、`model/api.ts`（只读契约）。
- **验收**：
  - [ ] 1 / 2 / 3 / 超过 3 个成员的组均有明确展示规则，叠卡总数始终使用全部 `members.length`。
  - [ ] 空组、无匹配、搜索强制展开行为不被叠卡改动。
- **风险**：多组共享同一库是既有能力；不得把组成员关系误改成单组移动。

### P1 — 卡片叠卡增强（round 002 实施）

只改 `KnowledgeView.tsx` 内 `GroupStack` 及 `renderGroup` 中它的调用；除非验收证明必须，不改 `LibraryCard / LibrarySpine / LibraryRow`。

1. **让叠卡标识完整**
   - 给 `GroupStack` 增加 `groupName: string`，由 `renderGroup` 传入 `group.name`。
   - accessible name 改为包含组名与总数的“展开某组，共 N 个资料库”语义；可见组名仍由现有组标题承担。
   - **验收**：折叠组只保留一个叠卡按钮、一个 Tab 停靠点；读屏名称能区分不同组，Enter / Space 与点击均展开，标题按钮的 `aria-expanded` 随状态更新。

2. **收敛层叠几何与层次**
   - 把现有 `104 / OFFSET 11 / INSET 6` 等几何值收为 `GroupStack` 附近的具名常量，容器高度统一由卡高、可见层数和纵向间距计算。
   - 保持第一张卡在最上层、后续卡依次向下且左右内收；可见层数固定为 `min(members.length, 3)`，第 4 个及以后只计入总数，不增加 DOM 层和叠卡高度。
   - 用边线、阴影和同组 `skin.accentBar` 拉开前中后层次；采用二维纵深，不加 3D 翻转、透视或大角度倾斜。
   - **验收**：1 层无多余底部留白，2 / 3 层间距一致；4 个以上成员与 3 个成员的叠卡同高；所有层保持同组色沿，后方卡不遮挡顶卡标题、读数和操作提示。

3. **让顶卡只表达一组清晰信息**
   - 顶卡保留当前资料库短名、`indexed_count / source_count`；底部将现有“点开看这 N 个库，另 N 个”改为不重复计数的“共 N 个资料库 · 点击展开”同义短文案。
   - 后方卡只承担层次提示，装饰内容设 `aria-hidden`，不形成额外控件；长库名继续单行截断。
   - **验收**：N=4 时只出现 3 层且文案总数为 4，不再出现“共 4、另 1”式重复；0 资料、长中文名与长英文名的顶卡均不溢出。

4. **把 hover 从一卡上移收敛为整叠响应**
   - 以现有 `group/stack` 为唯一交互状态来源：顶卡小幅上移，后层仅做更小的跟随或阴影 / 边线变化，整叠仍保持收拢；使用 `transform` 与透明度 / 阴影过渡，不在 hover 时改文档流尺寸。
   - 首版时长沿用约 200ms，缓动采用项目现有克制风格；同时提供清晰 `focus-visible` 样式，键盘焦点与 hover 有一致的层次反馈。
   - 为新增位移和过渡补 `motion-reduce` 降级：减少动态时取消叠卡位移，展开功能与内容不变。
   - **验收**：指针进入、在层间移动、离开时不跳层、不闪烁、不触发布局抖动；键盘聚焦有可见轮廓；系统减少动态下无叠卡位移动画。

5. **保住已有交互与响应式边界**
   - 保持 `GroupStack` 的挂载条件、`toggleGroup`、搜索强制展开、组拖放目标、组菜单和其他视图行为不变；本轮不做展开 / 收起的 FLIP 或共享元素动画。
   - **验收**：在 390px 与桌面宽度分别检查 1 / 2 / 3 / 5 个成员的组，无横向溢出、遮挡组标题或遮挡下一组；展开后仍是原 `LibraryCard` 网格，点击库卡仍进入 `Paths.kb(library.id)`。

**round 002 验证证据**：在 `heli-web` 执行 `npm run typecheck`、`npm run build`、`npm run check:routes`；再用浏览器覆盖上述成员数、390px / 桌面、键盘、减少动态和展开后导航，记录检查结果与必要截图。未实际执行的检查不得勾过。

- **P1 风险**：绝对定位高度与偏移必须同源，否则层数变化会留白或裁切；后方卡可见文字与读屏重复需一起处理；叠卡按钮在整个折叠视图分支复用，不能误改书架 / 列表的展开语义。

### P2 — 书架书脊到书面（后续轮）

- **做**：在现有 `LibrarySpine` 的抽出 / 转封面机制上补最小信息集的最近更新时间，收敛 hover / focus 过渡。
- **不做**：不重写书架、不引入新 3D 框架、不与 round 002 同轮实施。

- **验收**：
  - [ ] 书面展示名称、资料总数、可检索数、最近更新时间及可选年份跨度，数据来自现有 `Library`。
  - [ ] 鼠标从书脊移到书面不反复收回，键盘可触发同等信息与进入单库操作。
- **风险**：封面当前 `pointer-events-none`，新增交互前必须重新设计命中区域，不能直接把封面变成第二套导航入口。

### P3 — 单库管理落地（沿用现状，后续只回归）

- **做**：保持所有库入口到 `/knowledge/<slug>` 的 `LibraryView`，默认展示库内资料管理 / 预览。
- **不做**：不新建库内页面，不改文档路由。

- **验收**：
  - [ ] 展开叠卡后点击任一库卡，进入该库而不是固定进入顶库；刷新后仍在该库。
  - [ ] 卡片、书架、列表三种入口目标一致。
- **风险**：叠卡自身的点击只负责展开，不能与库卡导航混用。

### P4 — 同组视觉与动效收敛（随各视图小步完成）

- **做**：继续使用 `spineSet(group.hue)` 共用色沿 / 书脊；round 002 只收敛叠卡参数，书架动效在 P2 收敛。

- **验收**：
  - [ ] 同组叠卡色沿与展开后的库卡归属色一致，未知 `hue` 仍回退中性色。
  - [ ] 新增动效均有减少动态降级，且不依赖新增依赖。
- **风险**：Tailwind 类名必须保持完整字面量，不能把现有 `spineSet` 改为运行时拼接类名。
